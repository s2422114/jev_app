## 1. 実験16・18：余計な情報を足しても動かなかった（ただし検証は弱い）

| ケース | state に足したもの | score | confidence |
|---|---|---|---|
| exp16_single | なし | 2.000 | 1.000 |
| exp16_with_others | 他の銘柄3社 | 2.000 | 1.000 |
| exp18_clean | なし | 2.000 | 1.000 |
| exp18_with_noise | 市況2本＋他社の不祥事 | 2.000 | 1.000 |

**4つとも完全に同じ。** 他社のネガティブなニュースを入れても、評価は動かなかった。
公式の `対象銘柄.決算コメント` を名指しする書き方が効いている。

### ただし、これは「動かなかった」証明として弱い

**4つとも天井（2.000 / conf 1.000）に張り付いている。**
「動かなかった」のか「天井で動きが見えないだけ」なのか、この結果からは区別できない。

B の実験5とまったく同じ問題。蒼井フーズのコメントが前向きすぎるため、
上に動く余地がない。

**追試が要る。** 判断が割れる材料（榎木商事や千鳥化学のコメント）を対象にして、
強く反対方向のノイズを足せば、初めて意味のある検証になる。

jaggedness は「無関係な情報が増えると精度が落ちる」と明記している。
**今回の結果は、その警告を否定するものではない。** 検証できていないだけ。

## 2. 実験17：長文のほうが確信が高かった（予想と逆）

| ケース | positivity | confidence | operating_down |
|---|---|---|---|
| short（2文） | 0.960 | 0.930 | 0.970 |
| long（決算短信風） | **0.990** | **0.980** | 0.980 |

予想は「長文だと確信度が下がりそう」だったが、**わずかに上がった**。

数字が埋もれた長文でも、営業減益という事実を正しく拾えている（0.98）。
長さそのものは、この程度なら問題にならない。

### 差はごく小さい

0.960 と 0.990、0.930 と 0.980。ぶれの範囲かもしれない。
**「長文でも壊れなかった」までは言えるが、「長文のほうが良い」とは言えない。**

## 3. 実験17でもう1つ：ここでは逆に、こちらが決めつけていた

予想は short が 0（後ろ向き）、long が 0.5。実際はどちらも **1 付近（どちらとも言えない）**。

榎木商事のコメントは「売上 +6.2%、営業利益 -4.8%、通期予想は据え置き」。
良い材料と悪い材料が混ざっている。**Jev の「どちらとも言えない」のほうが妥当。**

### A・B・C とはパターンが逆

これまでは「こちらが中間に寄せ、Jev がはっきり答える」だった。
今回は「こちらが 0 と決めつけ、Jev が中間に置いた」。

**違いは、質問の型と criteria にある。**

この Score には3段階が用意されていて、真ん中が
「良い材料と悪い材料が混ざっているか、どちらとも言えない内容。」と明記されている。
**Jev は、用意された「どちらとも言えない」の置き場を正しく使った。**

### 実験15と同じ構造

C の実験15で、「該当なし」を入れたら正しくそこに入れ、
入れないと無理やり「人事」に分類した。まったく同じことが起きている。

**逃げ場を用意すれば Jev は正しく使う。用意しなければ、どちらかに倒れる。**

C の実験10で、同じような「売上最高だが赤字」のコメントに Noul で聞いたときは
0.19（ネガティブ寄り）だった。あれは「はい/いいえ」しかなく、
「どちらとも言えない」の置き場がなかったから。

**設計への示唆：判断が割れうる問いには、中間の置き場を用意する。**
Noul で聞くと必ずどちらかに倒れる。Score の3段階か、Choice に中立の選択肢を置く。

`exp16_single` と `exp18_clean` は、state も質問も同じリクエスト。

| | score | confidence | 入力トークン |

| exp16_single | 2.000 | 1.000 | 533 |
| exp18_clean | 2.000 | 1.000 | 533 |

**完全に同じ値。** 実験25（同じリクエストを何度か）の先取りになった。

ただしこれも天井での一致なので、**中間の値でも安定するかは別途確認が要る。**
A の -2.9% と -3.1%（0.48 と 0.47）のような微妙な差が、ぶれなのか本物なのかは、
この結果からは判断できない。

## 5. usage：ノイズは答えを変えなくてもコストは食う

| ケース | 入力トークン | 増分 |
|---|---|---|
| exp16_single | 533 | — |
| exp16_with_others（他社3社） | 903 | **+370** |
| exp17_short | 569 | — |
| exp17_long（長文） | 878 | **+309** |

他社3社を足すと入力が **1.7倍**。長文にすると **1.5倍**。

C で分かった「質問を足すのは約37トークンで安い」と対照的。
**state を膨らませるのは高い。**

- 質問を増やす → 安い（1問 37トークン）
- state を増やす → 高い（1社 120トークン前後）

公式の「ask a lot of questions」「send only what the question needs」が、
この2つの数字の対比そのものになっている。

今回の規模では料金は無視できるが、**フィルタは精度だけでなくコストの話でもある。**

## 方針への影響

- **state の名指しは効く。** `対象銘柄.決算コメント` のように指せば、他の情報があっても答えは動かなかった
  （ただし上記のとおり検証は弱い）。本番でもこの書き方を続ける。
- **判断が割れうる問いには、中間の置き場を用意する。**
  実験15（該当なし）と実験17（Score の真ん中）で同じことが確認できた。
  Noul で聞くと必ずどちらかに倒れることを、設計の前提にする。
- **state は絞る。** 答えが変わらなくても、コストは素直に増える。
- **長文は、この程度なら問題にならない。** 決算短信風の長さでも事実を拾えている。

## 追試したいこと

1. **判断が割れる材料でのノイズ検証**（実験16・18の続き）
   榎木商事や千鳥化学のコメントを対象にして、強い反対方向のノイズを足す。
   天井に張り付かない材料でないと、検証にならない。
2. **中間の値での安定性**（実験25）
   今回の一致は天井での一致。0.4〜0.6 あたりの値が安定するかは別問題。
